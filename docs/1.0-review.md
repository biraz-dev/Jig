# Jig 1.0 scope and stabilization review

Reviewed 17 November 2026 by independent reviewers covering user experience,
data reliability, performance, and product scope. The review assesses readiness for the existing personal-utility scope.

## Scope

Jig has enough functionality for its intended purpose: a local place to capture
information, plan work, calculate, draft text, and keep portable files. The
existing paths connect without requiring projects, accounts, or a backend:

- Draft and Notes feed Tasks while retaining useful text.
- Tasks, calendar dates, timeline bars and Gantt charts use the same records.
- Sheets feed live Charts and small cell-linked controls.
- JSON and Jig ODS preserve the document; settings travel separately.

The feature set is complete for this scope. Further work should improve the
reliability and legibility of these paths rather than add another workspace.

## Fixes from the review

| Finding | Change |
| --- | --- |
| The ODS save label did not reveal that the file contains the whole workspace. | Renamed it as a Jig backup and added scope help before download, explicitly including Notes, Draft and calculator history. CSV/PDF remain sheet-sharing formats. |
| Draft had no keyboard entry route from other workspaces. | Registered Ctrl+Alt+R in the existing editable shortcut system; legacy custom bindings retain ownership of that chord. |
| Escape from Draft formatting controls behaved differently from the editor. | Escape now returns to the app across the panel, with local link cancellation preserved. |
| A valid self-closing empty ODS sheet could disappear during import and break references. | Shared sheet creation between normal and empty XML elements; added empty-sheet, reference, roundtrip, name and sheet-limit regressions. |
| The chart gallery evaluated the entire workbook again for each scene. | Reused its existing Evaluation across charts, resizing and palette changes; export convenience APIs retain their behavior. |
| Task rendering repeatedly searched all tasks/deadlines for each dated row. | Built deadline ownership and date indexes once per render. |
| An XML parser counter was named as depth but redundantly counted starts. | Removed it; the independent XML event budget and actual nesting limit remain. |

The chart optimization was measured in a native release probe with 20,000
literal cells and 16 small charts: median scene construction fell from 102.079 ms
to 6.428 ms over seven measured rounds after warmup. Rebuilding the scenes with
an already cached Evaluation took 0.067 ms. These are controlled native timings,
not measurements of browser frame rate or typical small documents.

An optimized task-loop probe also confirmed the quadratic search pattern:
5,000 dated tasks took approximately 15–17 ms versus 1.8–1.9 ms with indexes.
This measures the search loops, excluding UI layout, and establishes the reason
for the small indexing change rather than a whole-app speed claim.

## Design and remaining polish

Reviewed browser captures show coherent desktop and narrow phone layouts for
Draft, Charts, Tasks and Notes. Keep the fixed-panel structure and the compact
toolbar conventions. The named themes, System mode and an optional custom
palette provide appearance choices without changing document colors.

Touch hit areas on dense task rows and note-card controls are a useful future
polish target. Current captures show wrapping without overlap; broader real
device use should determine whether missed taps warrant larger hit regions.
This is not a reason to redesign the application or grow its feature set.

Continue protecting committed and unfinished text, testing restoration, and
keeping save/export wording precise. Browser data belongs to its profile and
site origin. Jig ODS is a whole-document backup, including its embedded private
workspaces. Financial document import organizes data for review; it does not
calculate or file taxes.

## Follow-up refinement

A final bounded sweep kept the existing feature set and panel layout. It found
two edge cases worth fixing:

- Removing the owner of an open date editor could leave stale schedule fields
  that blocked editing another task. Successful deletion, clearing completed
  tasks and moving a task to Notes now close the orphaned editor completely.
- A conflicting Draft recovery copy could remain only in tab-local storage
  without activating the existing unload protection. Recovery-only text now
  counts as unsaved; copying it still preserves the journal, and ordinary
  successful saves clear the unsaved state as before.

Regression checks exercise reopening date editors and restoring the saved
document after those removals, plus conflicting recovery, copy, refresh and
normal save acknowledgements. The additional themes, Charts and sheet-control
review found no further actionable defects. Larger touch targets remain a
real-device polish question rather than a reason to change the working layout.

## Comparison with established tools

Primary product pages checked during this review:

| Project | Its documented depth | What that means for Jig |
| --- | --- | --- |
| [Super Productivity](https://super-productivity.com/) | Subtasks, repeating tasks, time tracking, timeboxing, integrations and optional sync. | Jig can offer simpler planning with adjacent numerical tools. |
| [Joplin](https://joplinapp.org/) | Multimedia notes, clipping, rich-text/Markdown editing, plugins and synchronized notebooks. | Jig's small Notes board and single Draft should promise quick capture and preparation. |
| [Grist](https://www.getgrist.com/product/) | Related tables, linked views, pivots, access controls, APIs and Python formulas. | Jig's spreadsheet controls suit personal calculations without requiring database or collaborative-app scope. |
| [Obsidian](https://obsidian.md/) | Local open files, links, graph, Canvas and plugins. | Jig's distinction is having planning and numerical tools immediately available together. |

These comparisons describe scope; they do not establish relative performance
or reliability. Jig does not need specialist feature parity to complete 1.0.

## Release discipline

Formatting, strict native/WASM Clippy, Rust tests, and the real-browser suites
remain release gates. The browser checks include existing workspaces, imports,
backups, shared history, themes, keyboard/touch actions and portable files.
Deployment records the exact commit and checks the public release marker,
index and WASM MIME type. Scope is ready; a release should be called verified
only after those checks pass for its exact build.
